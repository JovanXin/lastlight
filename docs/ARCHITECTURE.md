# Architecture

Lastlight is deliberately small and dependency-free. Everything that decides
whether a hiker turns around in time is plain, readable JavaScript that can be
tested without a browser.

## Principles

1. **Safety maths is pure and tested.** No module under `src/core/` touches the
   DOM, the network, or the clock implicitly. Every decision is a function of
   explicit inputs, which is why the whole engine runs in Node under `node --test`.
2. **No runtime dependencies.** The app is ES modules loaded directly by the
   browser. There is no build step, so there is no supply chain to trust in the
   places where the app is used. The only dev-time tool is a static file server.
3. **Fail soft.** Weather, elevation and map tiles are optional. If they are
   unavailable the app still routes, schedules and warns; it just has less context.
4. **Progressive enhancement.** The app works as a web page, improves as an
   installed PWA, and is most useful with a GPS fix.

## Module map

| Path | Responsibility |
| --- | --- |
| `src/core/geo.js` | Haversine distance, linear-referenced route profiles, elevation gain/loss, resampling |
| `src/core/pace.js` | Tobler hiking function, moving ratio, cumulative schedules and their inverses |
| `src/core/solar.js` | Low-precision solar position, sunrise/sunset, three twilight bands, polar day/night |
| `src/core/turnaround.js` | Furthest safe point, strategic and tactical deadlines, verdicts, bailout ranking, loop slack |
| `src/core/planning.js` | Latest daylight-safe start, feasible finish, darkness duration |
| `src/core/gpx.js` | Dependency-free GPX 1.1 import and export |
| `src/services/storage.js` | Saved trips in IndexedDB, last session in localStorage |
| `src/services/weather.js` | Open-Meteo forecast and elevation, cached, fails soft |
| `src/services/location.js` | GPS projection onto the route and a geolocation wrapper |
| `src/ui/map.js` | Canvas slippy map: tiles, pan/zoom, route, markers, night filter |
| `src/ui/profile.js` | Elevation profile with scrubbing, turnaround and bailout markers |
| `src/ui/sharecard.js` | Shareable safety card (canvas) and check-in plan text |
| `src/ui/format.js` | Duration, distance, clock and verdict formatting |
| `src/app.js` | State store, derivations and all DOM wiring |

## Data flow

```
user input ──▶ store.set(patch) ──▶ computeDerived(state) ──▶ render(state, derived)
                                          │
             profile ── schedules ── analysis ── bailouts ── planning
```

`computeDerived` is the single place where raw state (route, pace, times) turns
into the numbers the UI shows. Renderers never compute safety decisions
themselves; they only format `derived`. That keeps the logic testable and stops
the display from drifting away from the model.

## Rendering

- The map and the elevation profile are hand-drawn on `<canvas>`, scaled for
  high-DPI screens and redrawn through `requestAnimationFrame`.
- The night map is produced by filtering OpenStreetMap tiles on the canvas, so
  no tile provider key or third-party licence is involved.
- Route overlays are drawn after the tile filter is reset, so they stay legible.

## Offline

- `sw.js` precaches the app shell and serves tiles stale-while-revalidate.
- Saved trips live in IndexedDB; the last session is restored from localStorage.
- Weather and elevation lookups are cached for 30 minutes and never block the UI.

## Testing

- `npm test` runs the core and service modules under Node's built-in test runner.
- Browser behaviour (map, modals, GPS, clipboard, downloads) is checked with a
  headless Chromium smoke test during development.
- Screenshots in `docs/screens/` are regenerated by those checks.

## Extending

Add safety maths to `src/core/` with tests first, then expose it through
`computeDerived` and a renderer. If a change touches how the turnaround is
computed, add a case to `test/turnaround.test.js` so the reasoning is recorded.
